Termômetro Zero como motor reutilizável

Como construir o primeiro jogo de forma que ele não seja apenas um jogo – e sim a base estrutural de onde os próximos nascem

Jogo Termômetro Zero Stack Unity Público Ensino técnico, 16–20 anos Destinatário Game designer / programação Status Em desenvolvimento

Por que este documento existe

O Termômetro Zero é o primeiro jogo do The Blue City, mas o objetivo dele é duplo: ele precisa ser um jogo completo e bom e precisa ser a primeira instância de um padrão que vai se repetir. A plataforma vai receber muitos jogos, e a meta é que cada jogo novo custe cada vez menos para nascer – porque a estrutura já existe e só o conteúdo muda.

Para isso funcionar, a decisão de arquitetura tem que ser tomada agora, no começo. Reaproveitar um jogo construído como peça única é caro e frágil; reaproveitar um jogo construído como motor é quase imediato. A diferença está inteiramente em como o código é organizado desde o primeiro dia.

1O princípio: separar motor de conteúdo

A regra central é uma só: o que é estrutura mora no motor; o que é tema mora no conteúdo. O motor não sabe que o jogo fala de gases de efeito estufa – ele sabe que existem níveis, mentores, desafios e pontuação. O tema entra como dado, nunca como lógica.

MOTOR – não muda entre jogos

  • Sistema de 3 níveis e progressão entre eles
  • Sistema de mentores (como surgem, quando intervêm, como dialogam)
  • Loop de jogo e máquina de estados
  • Pontuação, feedback e regras de avanço
  • A mecânica-núcleo, abstraída do tema
  • UI / HUD / transições / telas
  • Carregador de conteúdo e validação do esquema

CONTEÚDO – muda a cada jogo

  • Tema, título e narrativa
  • Identidade dos mentores (nome, fala, visual)
  • Desafios e perguntas de cada nível
  • Parâmetros de dificuldade e balanceamento
  • Critérios pedagógicos vindos do GDD
  • Textos, imagens, sons e assets
  • Metas e mensagens de cada nível

Teste prático para saber onde cada coisa vai: se a informação muda quando trocamos o jogo de gases de efeito estufa por um jogo de outro tema, ela é conteúdo. Se ela permanece igual, é motor.

2O contrato: o esquema de conteúdo

A peça mais importante deste trabalho é o esquema de conteúdo – um formato estruturado e documentado que o motor lê para montar um jogo. Ele é a fronteira entre o motor e o tema, e é também o ponto exato onde o GDD vai se conectar à programação no futuro.

Abaixo, um esboço da forma esperada para o Termômetro Zero. Como o desenvolvimento é em Unity, o conteúdo pode entrar como JSON carregado em runtime (StreamingAssets ou Addressables) ou como ScriptableObjects – a escolha de implementação é sua, desde que o contrato conceitual seja este e fique documentado:

// conteudo-termometro-zero.json – instância de conteúdo
{
  "meta": {
    "titulo": "Termômetro Zero",
    "tema": "Redução de gases de efeito estufa",
    "publico": "Ensino técnico, 16–20 anos",
    "versaoEsquema": "1.0"
  },
  "mentores": [
    {
      "id": "mentor_01",
      "nome": "...",
      "aparece_em": ["nivel_1"],
      "falas": { "intro": "...", "acerto": "...", "erro": "..." },
      "asset": "mentor01.png"
    }
  ],
  "niveis": [
    {
      "id": "nivel_1",
      "objetivo": "...",
      "criterioPedagogico": "... (origem: GDD seção X)",
      "desafios": [ { "enunciado": "...", "parametros": {} } ],
      "pontuacao": { "max": 100, "avancoMinimo": 60 }
    }
    // nivel_2, nivel_3 ...
  ],
  "narrativa": { "abertura": "...", "fechamento": "..." }
}

O motor lê esse arquivo e monta o jogo. Trocar o arquivo – sem tocar no motor – produz outro jogo.

3Regras inegociáveis do motor

  1. Zero conteúdo escrito no código do motor. Nenhum nome de mentor, texto, pergunta, número de nível ou referência ao tema dentro da lógica. Tudo vem do esquema de conteúdo.
  2. Tema é dado, nunca lógica. Se for preciso um if que mencione "gases" ou "CO₂", algo está no lugar errado.
  3. O motor valida o conteúdo antes de rodar. Conteúdo fora do esquema deve falhar de forma controlada, com mensagem clara – nunca quebrar silenciosamente nem rodar com dado incompleto.
  4. O esquema é versionado. Cada conteúdo declara a versão do esquema que usa, para que jogos antigos não quebrem quando o motor evoluir.
  5. O contrato motor↔conteúdo é documentado. Um documento curto descrevendo cada campo do esquema – é o que permite que outra pessoa, ou o Fabulus, gere conteúdo válido depois.

4Por que isso importa além da economia

Conexão com o Fabulus

O Fabulus produz os Game Design Documents através do fluxo governado com checkpoints humanos. Com a separação motor↔conteúdo, o GDD passa a alimentar diretamente o esquema de conteúdo – e não código novo a cada jogo.

Isso muda a natureza do que precisa ser verificado: em vez de validar código gerado do zero (alto risco), o checkpoint do operador valida se o conteúdo encaixa no esquema de um motor que já foi testado uma vez. A superfície de erro despenca. É contenção de erro estrutural, não confiança no que a IA produz.

5Configuração ou motor novo

Essa arquitetura reduz drasticamente o custo de cada jogo novo enquanto ele couber na mesma família estrutural do Termômetro Zero: três níveis, mentores, mecânica do mesmo tipo. Nesse caso, jogo novo = conteúdo novo.

Atenção

Quando um jogo futuro exigir uma mecânica genuinamente diferente – não um tema diferente, uma mecânica diferente – o motor precisa ser estendido por um humano. Isso é template novo, não configuração. Por isso a meta não é um molde único, e sim uma família de templates, cada um cobrindo uma classe de mecânica.

Vale, na construção do Termômetro Zero, deixar claro no código o que é mecânica-núcleo (candidata a virar ponto de extensão) e o que é estrutura fixa. Isso facilita criar o segundo template quando ele for necessário.

6O que esperamos como entrega

  • O motor do Termômetro Zero arquitetado com a separação motor↔conteúdo
  • O esquema de conteúdo definido e documentado (o contrato)
  • O Termômetro Zero rodando como a primeira instância de conteúdo sobre esse motor
  • Validação de conteúdo implementada (o motor recusa conteúdo inválido)
  • Uma documentação curta do contrato, suficiente para outra pessoa gerar um conteúdo válido
